Getting Semantius **[Agent Skills](/docs/agent-skills)** running takes four steps: install the Semantius CLI, add the skills to your agent, sign the CLI in to your instance, then check the connection.

## 1. Install the Semantius CLI

The CLI is the bridge between your agent and your Semantius platform. Pick the installer for your OS.

### Linux and macOS

<Command command="curl -fsSL https://raw.githubusercontent.com/semantius/semantius-cli/main/install.sh | bash" />

The installer puts `semantius` in `/usr/local/bin` if you can write there, otherwise in `~/.local/bin`. It does not change your PATH: if the folder it installed into is not on it, it prints the line that adds that folder to your shell's startup file.

### Windows (PowerShell)

<Command command="irm https://raw.githubusercontent.com/semantius/semantius-cli/main/install.ps1 | iex" />

The Windows installer places `semantius.exe` in `%LOCALAPPDATA%\Programs\Semantius` and adds it to your user PATH, which only programs started afterwards see: open a new terminal, and restart any app whose terminals or agents should find `semantius`. Use this installer from Git Bash too, since `install.sh` does not support Windows.

Verify the install by running:

<Command command="semantius --version" />

## 2. Install the Skills

Pull the skill bundle into your agent. The installer needs Node.js 22.20 or later, and git. Leave the **Agent** dropdown on **All** to install for every detected agent, or pick a specific agent to target just that one. Toggle **Global** to install into your home directory instead of the current project.

<SkillInstall url="semantius/semantius-cli" includeSubagents />

Supports [OpenCode, Claude Code, Codex, Cursor, and 51 more](https://github.com/vercel-labs/skills#supported-agents). See the [skills documentation](https://github.com/vercel-labs/skills) to learn how to install skills for your agent.

Meta's Muse does not support a global installation, so install for its root agent instead:

<Command command="npx -y skills add semantius/semantius-cli --all --subagent root" />

---

The installer registers the Semantius skills (use-semantius, semantius-importer, semantius-transfer and others) with your agent. The skills call the local `semantius` binary, so the CLI you just installed is what does the actual work.

Start a new agent session after installing: an agent that is already running may not pick the skills up.

## 3. Sign In

Sign up for a Semantius data platform, or sign in to yours, at **[app.semantius.com](https://app.semantius.com/)**. Once your instance is provisioned, the dashboard's Get Started card shows its address, `https://<your-org>.semantius.app`. Connect the CLI to it:

<Command command="semantius use https://<your-org>.semantius.app" />

Unless a usable session for it is already stored, `use` opens your browser to sign in, then makes the instance your current host in every directory. From then on the CLI, and any agent using it, acts as you, with your permissions.

- **Not sitting at this machine?** On a server, in a container or an SSH session, or for an always-on agent, add `--login-flow device`: it prints a URL and a code to enter on your phone or laptop instead.
- **Self-hosted** instances work the same way: `semantius use https://semantius.example.com`.
- **Scripts and CI** can use an API key instead of a sign-in: see [Credentials](https://github.com/semantius/semantius-cli#credentials-sources-and-evaluation-order) in the CLI's README.

No config file is needed: the CLI's crud tools call your instance's API directly, and the CLI reaches the cube analytics server itself.

## 4. Verify the Setup

<Command command="semantius whoami" />

It shows the host, your user and roles, and when the session expires. Then ask your agent something only the skills can do, for example:

> "List the entities in my Semantius instance."

If the agent invokes a Semantius skill and returns your model, everything is wired up correctly. If you get a permission error, your user's role does not allow the action: adjust the role in the admin dashboard.
