---
title: "Data Catalog"
description: "The core of Semantius: modules, entities and fields, permissions and roles, business logic and audit logs, kept as data and enforced inside the database."
---

The data catalog is the core of Semantius. It describes your business as
data, covering the [modules](/docs/modules) that group an application, the
[entities and fields](/docs/entities-and-fields) that become database tables with a REST
API, the rules that govern them ([permissions](/docs/permissions-and-roles),
[business logic](/docs/business-logic), and a [RACI](/docs/raci) matrix for
state changes), and the [audit logs](/docs/audit-logs) that record every
change. Any change to an entity or field is applied to its underlying table in
the same transaction, so the model and the database cannot drift apart.

The data catalog is part of every edition of Semantius.
[Semantius Cloud](https://app.semantius.com) runs it for you,
[Semantius Open Source](/docs/self-hosted) runs it on your own machine or
server, and the [pg_semantius](/docs/pg-semantius) extension adds it to an
existing PostgreSQL database. In all three, rules are enforced inside the
database, ensuring that an agent, a script, and the web app all pass through
the same checks.

## Modules

A [module](/docs/modules) groups the entities, permissions and roles of one
application, such as a CRM or a helpdesk. Its
[version](/docs/modules#version) counts the changes to its model, and
[deleting it](/docs/modules#deleting-a-module) removes its entities with
their records, its permissions and its roles.

## Entities and Fields

An [entity](/docs/entities-and-fields) is a kind of record, such as a ticket or an
order. Saving one creates its table, its API endpoint and its access
policies. Each [field](/docs/entities-and-fields/fields) is a column of that table, and
its [format](/docs/entities-and-fields/formats) decides what the database accepts.
[Relationships](/docs/entities-and-fields/relationships) link records to each other, and
[subtypes and extensions](/docs/entities-and-fields/relationships#subtypes-and-extensions)
share records with a base entity.

## Conventions

The [conventions](/docs/conventions) are optional naming and modeling
conventions: plural snake_case table names, record names people already use, a
`workflow_state` for every lifecycle, `<module_slug>:<action>` permissions. They
keep a catalog consistent, so that people and agents can read one module after
another.

## Permissions and Roles

[Permissions and roles](/docs/permissions-and-roles) decide who may read and write each
entity. Each entity names a view permission and an edit permission,
[roles](/docs/permissions-and-roles/roles) bundle permissions for users, and the
[hierarchy](/docs/permissions-and-roles/permissions#the-hierarchy) lets one permission include
others. Row-level security checks them on every request.

## Users and Agents

[Users and agents](/docs/users-and-agents) are the records of `users`: people
who sign in through an identity provider, and agents, service principals that
work through [API keys](/docs/users-and-agents/api-keys). Both hold roles and
permissions the same way.

## Business Logic

[Business logic](/docs/business-logic) is stored on entities and fields as
[JsonLogic](/docs/business-logic/jsonlogic) rules: computed fields,
validation rules and row-level select rules, which the database enforces on
every write and read, and field input modes, which forms apply as you edit.
The [JsonLogic extensions](/docs/business-logic/extensions) add the variables
and operators Semantius provides, and
[rollup fields](/docs/business-logic/rollups) aggregate the records of a
child entity.

## Audit Logs

The [audit logs](/docs/audit-logs) record every change to the records of
audited entities, and every schema change, in two append-only logs that only
administrators can read.

## RACI

[RACI](/docs/raci) gives roles a letter for each process: Responsible,
Accountable, Consulted or Informed. A process gate ties a process to a state of
an entity's records, and a record that enters the state notifies or consults
the roles the matrix names.

## Tables

The data catalog is kept in these tables of the
[administration module](/docs/modules#the-administration-module):

| Table | Description |
|---|---|
| [`modules`](/docs/modules#the-module-record) | Groups of related tables and permissions |
| [`entities`](/docs/entities-and-fields/entities#the-entity-record) | Catalog of tables in Semantius |
| [`fields`](/docs/entities-and-fields/fields#the-field-record) | Catalog of the fields that make up a table |
| [`permissions`](/docs/permissions-and-roles/permissions#the-permission-record) | System permissions that can be assigned to roles and organized via hierarchy |
| [`roles`](/docs/permissions-and-roles/roles#the-role-record) | Groups of permissions that can be assigned to users |
| [`user_roles`](/docs/permissions-and-roles/roles#grants-and-assignments) | Many-to-many mapping between users and roles |
| [`role_permissions`](/docs/permissions-and-roles/roles#grants-and-assignments) | Many-to-many mapping between roles and permissions |
| [`user_permissions`](/docs/permissions-and-roles/roles#grants-and-assignments) | Many-to-many mapping between users and permissions for direct per-user permission grants |
| [`permission_hierarchy`](/docs/permissions-and-roles/permissions#the-hierarchy) | Defines permission inclusion (including permission implies included permissions) |
| [`users`](/docs/users-and-agents/users#the-user-record) | Users and agents |
| [`processes`](/docs/raci#processes) | RACI process catalog |
| [`raci_assignments`](/docs/raci#raci-assignments) | RACI matrix rows assigning roles to processes |
| [`process_gates`](/docs/raci#process-gates) | Governance registry: maps entity transitions to processes |
| [`raci_events`](/docs/raci#raci-events) | Notify/consult audit log for RACI-governed record transitions |
| [`audit_record_logs`](/docs/audit-logs#the-record-log) | DML audit trail for entity table records |
| [`audit_ddl_logs`](/docs/audit-logs#the-schema-log) | DDL audit trail for schema change events |
